# Lista kontrolna przed udostępnieniem (spec §9)

Lista z `spec.md` §9: warunki udostępnienia aplikacji komukolwiek poza pierwszą parą testową. To nie jest zakres kodu MVP. Dokument opisuje **stan techniczny** na gałęzi `main` i to, co zostało; nie stwierdza zgodności z prawem. Pozycje prawne mają dopisek „do weryfikacji z prawnikiem”. Inwentarz danych, na którym oprą się dokumenty prawne: `docs/data-inventory.md`.

Stany: **zrobione w kodzie**, **dokument-szkic**, **wymaga właściciela** (decyzja, podpis albo działanie osoby), **M9** (etap Android i iOS, `plan.md`).

## Uwagi

- Testy end-to-end w przeglądarce (`e2e/`, `npm run e2e`) działają poza bramkami pipeline'u (`plan.md`, NFR-QA-03) i nie zastępują sprawdzenia na telefonach (M9).
- Dane w przeglądarce służą tylko do testów, nie dla prawdziwych par (`plan.md`). Szyfrowana baza SQLCipher, Keychain/Keystore i wyłączone kopie systemowe (NFR-PRV-01, NFR-PRV-02) są w M9, więc przed udostępnieniem poza pierwszą parę testową wymagają potwierdzenia.
- Retencja logów (14 dni, NFR-PRV-05): `services/relay/src/logging.ts` i `retention.ts` opisują pola i okresy; rotacja logów kontenerów jest ograniczona rozmiarem, nie czasem (zob. `docs/data-inventory.md`).
